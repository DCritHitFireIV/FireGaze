## ④ 建议的实现验收点

### A. 进实现前必须写死的规格（对应 ③）

1. **状态筛选的选项集**：逐字对齐徽标词表（未汉化 / 待应用 / 翻译中 / 待更新 / 已汉化 / 翻译失败 / 重载失败·已还原 / 未加载 / 无可译文本），支持与搜索、「只看第三方」叠加；「全部」加标签（如「汉化状态：全部」）或在展开帧里自明。
2. **「一键汉化」的状态行为矩阵**：未汉化 = 翻译 + 写入 + 重载；待应用 = 写入 + 重载；待更新 = 增量重翻 + 写入 + 重载；**已汉化且无变化 = 校验并提示「已是最新」**（不得静默全量重翻）。
3. **重翻失败（已有旧补丁）的徽标与收尾**：旧补丁状态必须保留可见（R1）。
4. **收尾行生命周期**：状态变化 / 刷新后清除，或本次会话内保留——二选一写死（R3）。
5. **任务锁范围**：翻译进行中，编辑器窗口的同名动作与其它行的「还原原文」是否可用；被拒点击给反馈（R4）。
6. **写入失败的收尾**：并入「应用失败」并复用自动还原 + 重试（R5）。

### B. 补帧 / 出图（第三版还原图）

- 补「状态筛选展开」帧，列出全部选项（A-1 的选项集）。
- 补「写入 / 重载阶段」帧——要么画出来（含 caption 承诺的「此步不能取消」文案），要么删掉该承诺；重载阶段的行内提示一并确定。
- 修正样例自洽：SimpleTweaks 版本号与帧 1–3 一致；若帧 3→4 视为同一时间线，工具栏「已汉化 12」需随 BOCCHI 完成 +1（否则在图上注明各帧独立场景）。
- 沿用项目既有规矩，出图后做一次「图 vs 实现」逐项对照（按钮名、计数、行数、勾选态必须闭合）。

### C. 实机验收（静态图无法验证）

- ⚠ 的悬停：给出一条完整原因 + 建议动作；修改译文 / 标不翻后 ⚠ 的消解规则（自动还是手动复核）要明确。
- 收尾行在滚动、刷新、切换页签后的出现与消失；切换页签后任务是否继续、能否取消、回到本页状态行是否还在。
- 状态筛选在 198 项下的过滤结果与徽标一致；「已汉化 12」口径（插件数）在悬停里说明。
- 「还原原文」：确认弹窗或 tooltip 说明范围（仅该插件 / 自动重载 / 译文是否保留 / 可再次汉化）。
- 重载失败时是否可在悬停 / 展开看到更具体原因（插件报错、文件占用）。
- 图标为真实插件图标 + 缺图标回退；13px 灰字（页首两句、收尾行、图例）在 100% / 125% 缩放下的可读性。
- 编辑器批量翻译后，用户是否会漏点「应用汉化」（状态行已给指引，实机确认点击率 / 误点）。

### D. 任务型验收（各 5 次，沿用 v1 方法）

1. 冷启动一次点对页签（记录误点「简介汉化」次数）。
2. 把一个未汉化插件一键汉化到中文界面（≤2 次点击、无额外询问）。
3. 5 秒内找出翻译失败 / 重载失败的插件（展开筛选后）。
4. 对一个已汉化插件点「一键汉化」，记录提示是否清楚（验证 R2 的「已是最新」语义）。

### E. 文案规范自查（项目规则，实现前勾一遍）

- **括号**：状态行 / 提示行里的解释性括号按项目规则清理，现清单：`（原始文件已备份）`、`（DPAPI 加密）`、`（悬停看原因）`、`（若为空则显示「未保存」）`、`（这一段只在选中免费通道时出现）`——改成逗号句、第二行灰字或 tooltip。
- **单位**：`条` / `处` 仍混用（`已翻译 65 条` vs `已汉化 11 处`）；若 v1 F18 未判「不修」，在 tooltip 里各定义一次或统一口径。
- **术语**：编辑器筛选里「候选 78」与「全部 78」并排且数值相同——确认两者差异（若同义则合并；若「全部」含灰名单则数值应闭合）；「灰名单」的解释在列表页展开区仍缺（编辑器与设置已有）。
