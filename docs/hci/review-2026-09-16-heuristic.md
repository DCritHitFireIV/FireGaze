**方法**：静态图逐元素核对 + 与同目录实现对照。基线实现已存在，我读了原代码做交叉验证，因此下文能把「图上看到的」和「实现里真会发生的」分开标注。引用格式：`文件:行`。

## 2. 最严重的 5 个问题
1. **默认预选 + 计数/视图不一致（A5-1 + A5-2，sev 4）**：状态行声称"问题项已自动勾选"，实现确实自动勾选全部 90 项（含 3 个"连接失败"），而图上的按钮却是`（3）`、表里 3 个勾——图冻结了一个实现中不可能出现的状态，正好把最危险的默认状态藏掉了。删一次就是 90 个库。
2. **"连接失败"没有在界面上被降级说明（A2-3，sev 4）**：它是网络/超时/证书，不代表库坏了，但界面只给灰字，且把它默认纳入待删集合。
3. **撤回只有一步，历史 10 条却静默丢弃（A3-3，sev 3）**：产品承诺"可以随时撤回"，实际连续两次操作后第一批不可撤回。
4. **删除确认弹窗不列清单（A5-3，sev 3）**：只有数量，没有 URL，无法在最后一步核对范围。
5. **整页按 13px 网页字号排版，真机 CJK 字号下三行控件会溢出裁切（A8-3 同类问题，sev 3）**：统计行在 13px 下已占行宽约 92%、过滤行约 91%、动作条约 83%（真实 `Describe()` 文案"删除 84 个仓库"还要更长），而 ImGui 的 `TextUnformatted`/`Button` 行**不会自动换行**。放大到常用字号（≈1.3×）后"上次体检时间""可用/已停用过滤器""打开备份目录"都会被切掉，且 HTML 的 `flex-wrap` 把这个问题掩盖了。

## 4. 需要结构性重构的问题（不是调样式能解决的）
1. **选择模型缺少"作用域"概念**：目前只有一个扁平 `selected` 集合（RepoAuditTab.cs:12），过滤器只是显示层的 `Filtered()`（349-370）。结果是"全选"跨视图生效、勾选项可以不可见、计数无法与屏幕核对。需要显式的"当前视图选择 / 全库选择"两态 + 选择集摘要面板。
2. **恢复机制只有一层且不在界面上有历史**：`UndoHistory`(10 条, Configuration.cs:107) 与 UI 只暴露 `[^1]` 不匹配。需要"操作历史"面板（动作/数量/时间/备份文件 + 逐条撤回）。
3. **千行列表缺少检索骨架**：无搜索、无排序、无分组。1200+ 行的审阅任务需要一个可查询的列表模型，而不是"5 个预设过滤器 + 逐行勾选"。
4. **顶部文档块代替了帮助体系**：三段散文承担了"是什么/术语/后果/恢复策略"四件事。需要折叠说明 + 行内 ⓘ + 帮助入口三层结构。
5. **单行排布假设**：三行控件（统计/过滤/动作）都假设"700px 一行放得下"，这是按 13px 画的。需要按 ImGui 字号做分组分行（尤其恢复类右对齐），否则再加任何控件都会溢出。

## 5. 三行说明文字要不要收敛——要，且要压到 1 行
| 现状 | 判断 | 处理 |
|---|---|---|
| 第③块（正文，2 行）"扫描你添加的全部第三方仓库（包含已停用的）：检查链接还能不能用、内容是不是合法的仓库文件（与卫月同款校验）。" | 太长，且"全部…包含已停用的"与复选框矛盾 | 压成 1 行："扫描全部第三方仓库（默认含已停用）：查链接是否失效、内容是否合法。" |
| 第④块（灰字，2 行）"内容不合规 = ……" | 概念定义不该常驻页面；但**信息本身不能删**（见第 6 节） | 下沉到状态单元格的 ⓘ tooltip；行内只留"内容不合规 ⓘ" |
| 第⑤块（灰字，1 行）"死链 / 内容不合规的库可以一键停用，或直接删除；删除前会自动备份，删除后可以随时撤回。" | 纯重复：删除语义在确认弹窗里、备份/撤回在状态行与按钮上各说了一遍 | 直接删除 |
合计省下约 84px 垂直空间——在 620px 窗口里相当于**多显示 2–3 行仓库**（当前表格可视高度只有约 250px ≈ 7–8 行，却要处理 90 个问题项）。

## 6. 「内容不合规 = …」这句讲清后果了吗——**一半**
原文：*"内容不合规 = 拿到的不是合法仓库文件：插件安装器无法识别这些条目，可能导致插件列表残缺或排版错乱。"*
- **讲清了**：是什么（不是合法仓库文件）、对安装器的影响（识别不了这些条目）。
- **没讲清**：① 对用户的实际后果——"这个库里的插件会全部加载不出来/收不到更新"（现在的"列表残缺或排版错乱"含糊且偏码农视角）；② **该怎么办**。图上第 2 行 `…/Jinjyu1211/AllHud/blob/main/repo.json` 正是"把 GitHub 网页链接当仓库链接填了"，正确修法是把 `/blob/` 换成 raw 直链——而页面只提供停用/删除，等于逼用户删掉一个只是填错链接的库。
- 改写建议（放到 tooltip / 行内）：「**内容不合规：这个链接返回的不是仓库 JSON（常见原因：填了 GitHub 网页地址而不是 raw 地址）。该库的插件会全部加载不出来。**」并配套一个`修正链接`（或`复制 raw 链接`）动作。

## 7. 专问：动作条放在列表正上方 vs 正下方
**结论：放上方更好，维持现状方向；但要拆成"左侧选择类 + 右侧恢复类"。**
| 维度 | 上方（现状） | 下方 | 判断 |
|---|---|---|---|
| 邻近性 | 与紧邻其上的"显示"过滤器、`全选问题项/清空选择`构成"筛选→选择→执行"的自上而下序列 | 与选择工具之间隔着整张表格（本页约 250px），勾完后视线与鼠标要跨过列表 | **上方胜** |
| 误触 | 与行内点击区（表格左下角勾选列）之间隔着一整张表，鼠标不易滑入 | 恰好在最后一行勾选框下方十几像素；连续快速点勾选框时容易落到`删除所选`上 | **上方胜** |
| 长列表 | 表格自带 ScrollY，按钮条无论上下都常驻可见——**长列表这个维度上两者等价** | 同上 | 平 |
| 可发现性 | 首屏一次看到说明/扫描/统计/过滤/动作，且"撤回上次操作"这种"随时能救回来"的心理保障立刻可见；也天然满足"撤回任何时候可见"的硬性要求 | 需要先接受一张满屏表格才会看到操作入口 | **上方胜** |
**最推荐布局（700×620，自上而下）**：
```
标题栏 / 页签
B  1 行说明 + [说明 ▸] ……………………………… 右: 上次体检 20:05
C  [开始体检 / 取消扫描]  ☑包含已停用的库
D  共 1241 · 问题 90（死链 85 / 内容不合规 2 / 连接失败 3）· 已停用 42
E  显示 ○问题 ○全部 ○死链+违规 ○已停用 ○可用   [搜索 URL…]        显示 87/1241
F  [停用所选(3)] [删除所选(3)…] [全选当前(87)] [清空]   │   [撤回：删除 84 个(20:31)] [打开备份目录]
G  状态行（固定 1 行，不换行、不换高度）
表格（占满剩余高度，默认按严重度排序）
```
要点：动作条仍在列表正上方；`全选/清空` 从过滤行移进动作条（解决 A8-3 溢出）；恢复类（撤回/备份）右对齐并永远渲染；状态行固定 1 行避免高度跳动。
