## 二、本轮新增问题（本轮改动引入或使新代码承担的错误）
### NEW-1 · P2 · 状态行不区分"是哪个开关在生效"，在帧 3 这一态上给出误导性结论
- **证据**：`InstallerTab.cs:64-67` 只把"是否有任一开关开着"作为是否调用状态行的条件，`StatusText()` 内部却**只看拦截计数与恢复状态**、不看开关（`InstallerListScroll.cs:383-398`）。而拦截计数只在第一项开启时才可能非 0（`InstallerListScroll.cs:145` 的守卫 `config.BlockInstallerAutoRefresh && this.sawListContent`）。因此"只开第二项"的会话里，状态行**永远**是 `已生效 · 本会话还没遇到后台自动刷新`（还原图帧 3 正是这句，HTML:91）——同一屏上方橙色行刚说"后台刷新可能把记住的位置清零"（即刷新确实在发生），下方状态行却说"还没遇到后台自动刷新"，且用"已生效"给了一件可能时灵时不灵的功能背书（`:390` 的 `已生效` 前缀）。位置记忆的成败在这行里没有任何答案。
- **最小修法**：`StatusText(bool block, bool remember)`，按开关组合拼句：第一项关时不报拦截计数，改报 `位置记忆已开启（未拦截后台刷新：上面那项已关闭）`。
- **注**：这不是"图与实现不符"——实现与图**逐字一致**、实现字符串本身就是这个含义。
### NEW-2 · P2 · 位置恢复失败（GivenUp）在用户去看设置页之前就被复位，等于没报
- **证据**：`InstallerListScroll.cs:162`（`OnClosed()` 执行 `this.phase = RestorePhase.Idle;`）＋ `:390-392`（只有 `phase == GivenUp` 才显示"上次打开时的列表位置没能恢复"）。而 `OnClosed` 在安装器窗口关闭后每帧都会执行（`:110-118`）。用户的自然动线是"关掉安装器 → 打开本设置页"，此时 phase 早已复位，设置页只会显示拦截计数那一句 → AR-01 想解决的"位置记忆到底恢没恢复"在设置页基本无法看到（除"设置页与安装器同时开着"这一非常规构图）。
- **最小修法**：`OnClosed` 里把 `GivenUp` 转存为一个持久标记（如 `lastRestoreFailed = true`，直到下次恢复成功再清），`StatusText()` 优先读它。
### NEW-3 · P2 · "已生效"覆盖不到反射句柄失效这条静默死亡路径（AR-01 点名的第二类风险）
- **证据**：`InstallerListScroll.cs:341-346`——`ResolvePluginManager()` 返回 null 或 `PluginsReady/ReposReady/repoRefreshTask` 任一反射句柄为 null 时**直接 return，不记日志、不置任何状态**；`:452-456`（`serviceOpen`/`managerType` 拿不到）与 `:465-467`（字段/属性改名）都是"静默 null"。卫月一旦重命名 `repoRefreshTask`，卫月侧改名的结果就是：开关照旧画着勾、状态行照旧显示 `已生效 · 本会话还没遇到后台自动刷新`，功能其实已死——与 AR-01 的原始危害描述完全一致（该风险原报告点名的是"卫月或 ImGui 一升级"）。
- **最小修法**：句柄缺失/解析失败时置一个 `disabledReason` 字段（并只记一条日志），`StatusText()` 首支改成 `本次已停用（{disabledReason}）`；`Tick` 最外层 catch 也可顺手置同一位。
### NEW-4 · P2 · "改动立即保存，下次打开插件安装器时生效"对第一项不成立
- **证据**：`InstallerTab.cs:68` 给两个开关共用一句时机说明；但拦截是**每帧读 config**（`InstallerListScroll.cs:145`），勾上后只要安装器正开着且列表已铺开（`sawListContent`），下一次后台刷新立刻就被拦（`Plugin.cs:334-338` 写入 + `:340-344` 每帧 Tick）。只有位置记忆是"下次打开"才生效（`InstallerListScroll.cs:128-131`）。一句话把两种时机说成一种，会让用户白白重开一次安装器。
- **最小修法**：`改动立即保存：拦截即刻生效，位置记忆在下次打开插件安装器时生效。`
### NEW-5 · P2 · "改为默认关"的迁移完全静默：老用户功能被关、已记住的位置被删，页面上无一字提示
- **证据**：`Plugin.cs:63-71`（`Version < 3` → 两项置 false、`ListScrollY = null`、直接 `SavePluginConfig`，无 `Chat.Print`、无一次性提示）；改前默认值是开（上一轮 `...-heuristic.md` AR-07 引用的 `Configuration.cs:56,64` 均为 `true`）；`Configuration.cs:58,61,64` 现为隐式 false。已发布版本 `pluginmaster.json:8` = `1.0.0.23`，说明确有此前的用户群。升级后的可见结果是"以前会记住位置，现在每次都从头开始"，且没有任何解释入口。数据损失本身极小（一个滚动像素值），故不判 P1。
- **最小修法**：迁移时打一条一次性 `Chat.Print`（`安装器两项功能已改为默认关闭，可在 /firegaze → 插件安装器 里打开`），或让迁移只重置"从未被用户改动过"的字段。
### NEW-6 · P2 · 跨产物承诺与"默认关"直接冲突（介绍说会拦、出厂却是"未启用"）
- **证据**：`FireGaze.csproj:17-19` 的 `Description` 新增第三项"拦住插件安装器自动刷新"；`README.md:19` 同；`translations.json:21774-21779`（FireGaze 自身的市场简介，原文与译文同）仍写"**本插件按调用来源拦截这些后台刷新**，手动刷新与打开安装器不受影响"——而按本轮改动，出厂态（图 1）该功能是关的，设置页明写 `未启用（上面两个开关都关着）`，迁移还会把老用户也关掉。用户在安装器里读到的介绍与装完后看到的默认状态相反（"用词不统一"部分属上一轮 F9/AR-09 记录级；"承诺的行为默认不成立"是**默认关**这一改动新造出来的事实性冲突）。
- **最小修法**：三处介绍统一补"（默认关闭，可在设置页打开）"；`translations.json` 那一条随本版一起改。
- **证据边界**：`translations.json` 中 FireGaze 条目是否会被渲染到安装器里（自我条目是否走同一 Patch 路径）本轮仍未在仓库内验证——即使不渲染，它也是发行产物，按同一处修即可。
