## Summary
这四条新增要回答的问题（"这个库到底有没有在给我干活"）是真实问题，方案方向（列 + 排序 + 勾选框，+0 按钮）也对；但当前形态同时做了三件对既有任务（体检并清理坏库）不利的事：
1. **把一个正交维度塞进三个既有容器**：使用情况（本机装了没）被放进 ①与健康度并列的单选组、②同一条已经被"健康度 + 启用状态"混装的统计行、③一个可排序的数值列却用状态词填格。结果是三个地方的语义都被稀释（U1/U4/U7）。
2. **排序这件事在图上自己就不自洽**：帧 1（默认、未排序）表头已经画了 ▼ 而行序不是按已装排；帧 2（同样是未排序）表头又完全不能排序；且没有"回到默认严重度排序"的入口（U2/U3）。
3. **"本机没装"直接接在原有批量删除动线上，却没有任何后果与边界措辞**：帧 1/3 里被勾选的第一行恰好是「可用 · 已装 4 个」，下方就是「删除所选（2）…」；而产品自己承认的"未在使用 ≠ 没用"在三帧 HTML 里一个字都没有（U5）。再加上"读不到插件数据"会静默退化成"全都没在用"（U6），这条动线目前有真实的误删风险。
**P0 0 项；P1 6 项；P2 9 项。Merge verdict: BLOCK（改稿后可放行，见文末清单）。**

## 逐条回答本次评审重点
**a) 不读文档能否理解「已装 4 个 / 未在使用」与后果 —— 不能（U1/U11/U5）。** 三层缺口：①语法不统一（同一列混数字与状态词）；②与同页既有语汇（已停用 / 未记录 / 未检查）撞车，用户没有可借用的既有理解；③后果完全缺席——"4 个"意味着"删了会牵连 4 个插件"，但这句话在弹窗、tooltip、行内都没有。
**b) 图标开关的真实价值与代价 —— 价值真实，代价放错了地方（U14/U9/U10）。** 价值：帧 1 里第 1/4/5 行的地址字面完全相同（HTML:76、:79、:80 都是 `https://raw.githubusercontent.com/…/pluginmaster.json`），在"哪一行是哪个库"这件事上，图标行确实是图上唯一的区分物（注意实现是"头…尾"截断 `UiHelpers.cs:41-51`，前省略部分是作画偏差；但新增的 70px 固定列确实是从地址列拿走的，请按下限窗口 560px 再核算一次横向预算）。代价：它是"全局、加行高、重排列表"的，而收益是"局部、单行"的 → 把开销从全局改成局部（内联/单行展开）即可，不必砍掉这条需求。
**c) 悬停才显示名字 —— 是主要缺陷，但受影响人群需要更正（U10/U15）。** 先排除误判：这是在 Windows PC 客户端上的插件，触屏不是主场景（且 Windows 会把触摸合成为鼠标事件，ImGui 只会看到"按下"，hover 语义与触摸预期不一致）。真正受影响的是：①纯键盘/焦点导航用户（ImGui 的 `IsItemHovered()` 是否对 nav 高亮项返回真，取决于 Dalamud 是否启用 `NavEnable*` 与本仓库未设置的全局 flags——我检索了 `src/`，全仓没有任何 `ImGuiConfigFlags`/`NavEnable` 设置，故**必须实机验证**）；②手指/低视力/放大 UI 的用户（24px 方格 + 逐格悬停）；③所有人的操作成本：25 个插件=25 次悬停，且名字是这个控件的唯一内容。建议：名字就地（前 N 个图标带小字）或点击弹"该库插件清单"，tooltip 降级为补充。
**d) 排序状态是否可见 —— 可见但不可信（U2/U3）。** 帧 1 在未排序时画了 ▼、帧 2 又完全不能排序、且没有回到默认（严重度）排序的入口。三帧里没有任何一帧画出"未排序"的样子。
**e) 「未在使用」的删除动线是否有一键误删诱惑 —— 不是"一步"，但缺口在别处（U5/U6/U4）。** 现状护栏是"筛未在使用 → 全选当前（N）→ 删除所选（N）… → 模态确认 → 备份 → 可撤回"（`RepoAuditTab.cs` `DrawDeleteConfirmPopup`、`DisableSelected/DeleteSelected`），比"一键"重；真正危险的是：①做决定的依据可能是**假 0**（U6，反射失败/URL 微改）；②弹窗与行内都不说后果与边界（U5）；③"未在使用"这批恰好是产品自己承认"不等于没用"的那批，而新筛选给它开了一条直达批量删除的最短路径。三条修完，"诱惑"就变成"知情后的选择"。
**f) 四条新增是否让页面任务失焦 —— 部分失焦，主要是空间与语汇两条。** ①纵向：图标行按行加高（U14），mockup 因表格没铺满而低估了代价；②横向：「复选框 28 + 状态 150 + 已装 70 + 首次记录 82 = 330px」固定列吃在一个 700px 宽的窗口里（HTML:75），"是哪个库"让位给"这个库在不在用"，而识别库链正是体检任务的第一步；③语汇：这一页现在同时教三个正交维度（健康度 / 启用状态 / 使用情况），而体检任务只需要一个。建议把使用情况**收敛到一个地方**：保留「已装」列（它同时服务识别与排序），撤掉与健康度互斥的第 7 个单选，统计行分段显示。
