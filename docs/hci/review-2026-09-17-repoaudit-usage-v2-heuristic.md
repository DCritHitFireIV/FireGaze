## 二、本轮新增问题
### 1. P1 — 新控件落在"已经有别的控件"的动作条第二行，图纸把该行的两个按钮抹掉了
- **证据**：图纸第二行 = 摘要 + 两个复选框（`v2:86-87 / 132-133 / 170-171`）；实现里这一行 = 摘要（`RepoAuditTab.cs:370`）+ **右对齐**「撤回…」（`:374-419`，经 `SameLine(targetX)` `:388`）+「打开备份目录」（`:419`），实现自己还带"放不下就把按钮换到下一行"的分支（`:382-386`）。
- **为什么重要**：①按 14–17px CJK 粗估，本行需要 ≈ 摘要 220 + 只看本机没装的 120 + 显示插件图标 105 + 撤回 120–160 + 打开备份目录 105 ≈ **670–710px**，而窗口内容区 = 700−32 = **668px**（最小 560 时只有 528px）；②ImGui 的 `SameLine(offset)` 不会把你推回上一项右侧（`:388` 用的是绝对偏移，比当前光标小就会**重叠**）→ 要么和「撤回」叠在一起（撤回是这条破坏性动线的安全网），要么触发 `:382-386` 折到第三行，正好回到上轮要避免的"新增控件行"；③图纸删掉两个已有控件，验收方照图实现就可能把它们挪走/做没。
- **最小修法**：二选一。①方案里写明该行完整内容（摘要 + 两个复选框 + 撤回 + 打开备份目录），并按 528px 内容区核算——多半放不下，那就把 `只看本机没装的` 与 `显示插件图标` 挪到**筛选行第二行**（上轮 AU-8-3 的候选②"筛选行分两行：状态组 / 使用组"），动作条保持原样；②或补一帧把第二行画全，让宽度可核对。**需实机量**一次（命令见文末）。
### 2. P1 — 镜像/变体 URL 的假 0 仍会显示成确定的 `0 个`；第三态下弹窗文案未定义
- **证据**：`RepoScanner.cs:330-338`（`gh.atmoomen.top` / `gh-proxy.org` 把 raw 地址当另一条线路）；`DalamudRepos.cs:63-85`（URL 原样来自 `ThirdRepoList`，无 trim/去尾斜杠/大小写归一）；`grep -rn "InstalledFromUrl" src/` **无命中**；`v2:194-195` 两句在"数据不可用"下没有定义。
- **为什么重要**：改动 8 自称"避免假 0 被当成确定值"，但只覆盖了"读不到列表"这一半。剩下这一半在本仓库不是罕见路径（多线路是本插件的既有能力），而它落在**语法最像确定值**的 `0 个` 上，下面就是"只看本机没装的 → 全选当前 → 删除"。
- **最小修法**：①在方案里加一句口径：`仅在 URL 归一化（trim / 忽略大小写 / 去尾斜杠 / 已知镜像前缀还原）后仍无匹配时才显示 0 个，否则显示 —`；②写死第三态下弹窗两句的抑制规则（数据不可用时不得断言"其中 N 条本机没有从它装过插件"）。
### 3. P2 — 默认态排序箭头与比较器方向相反，且"状态列升序"≡"默认"
- **证据**：帧 1/2 状态列画 ▼（`v2:77/115`），而默认序是 `SeverityRank` **升序**（Dead=0 → Ok=6，`UiHelpers.cs:27-36`；`RepoAuditTab.cs:474-475`），死链在最上；同一份图给另一列建立的约定是"▼ = 按该列降序"（帧 3 caption `v2:144`）。
- **为什么重要**：默认态的标记与它自己的口径打架；且对 `状态` 列而言"升序"就是默认，三态回路里点第一次看不出变化（用户会以为排序坏了）。
- **最小修法**：默认态用 ▲ 或去掉箭头（只保留 `排序：默认（状态）` 文案），并写明"状态列的升序态 = 默认态"。
### 4. P2 — 两处新帧内部不一致
- 帧 2 表里只画 3 条库链，摘要仍写 `结果 5 行`、`全选当前（5）`（`v2:132/136`），且省掉的是**第一行**（帧 1 的死链行 `v2:78`）。静态图可以省尾行、不能省首行——否则读成"打开图标开关会把上面几行藏起来"。
- 帧 4 弹窗列出的两条（`v2:191-192`）与帧 1–3 的勾选不符：勾选集是 `内容不合规(1 个)` + `可用(4 个)`（`v2:79-80/116-117/163-164`），弹窗第二条却是**未勾选**的死链行（`v2:78/165`）。而弹窗第 3、4 句文案恰恰依赖这条 0 值行——为了演示新文案改了选中集却没同步表帧。
- **最小修法**：帧 2 省尾行（或画完 5 条并说明是滚动）；帧 4 把表帧勾选改成 `死链 + 可用(4 个)`，或加一句"（示例：另选了 1 条 0 值行）"。
### 5. P2 — 本轮新增的两个状态一个帧都没有；未扫描行能否勾选未定义
- **证据**：`grep "—" v2.html` 无 `—` 单元格、`未检查` 只出现在统计行 → 4 帧里没有"刚打开、未体检"和"插件数据不可用（整列 —）"的样子；实现里 `RepoAuditItem.IsSelectable => Status != Unknown`（`RepoScanner.cs:52`）已经表达了"未扫描行不可选"的意图，但当前 UI 从未使用它。
- **为什么重要**：改动 7、8 是这轮最重要的两条安全/时效设计，图上都无法验收；而"列表先于扫描存在"必然带来"未扫描行能不能直接勾选删除"的新问题。
- **最小修法**：补 2 帧（同一窗口：刚打开未体检 / 数据不可用），后者要画出 `—` 与 `0 个` 并排、状态行报错文案、复选框 disabled，并写明未扫描行的勾选规则。
### 6. P2 — `本机已装` 4 字 + 常驻 `⇅` 塞进 74px 固定列
- **证据**：`v2:77/115/161`（`width:74px`，同格放 `本机已装` 与 `⇅`）。14px 下 4 个 CJK ≈56px + 箭头 ≈10–14px + 单元格内边距 12px ≈ **78–82px > 74px**；实现字号更大时更紧（对照现状 `状态` 140px / `首次记录` 96px，`RepoAuditTab.cs:166-169`），而图上 URL 列本来就在截断。
- **最小修法**：该列加宽到 ≥96px，或列头缩成 `本机`+双向箭头、全称写进 tooltip；并在最小 560px 窗口下重算各列（固定列 26+132+74+70=302px 已吃掉内容区约 45%）。
### 7. P2 — 图标条"每项多一行"会让 `RowBg` 隔行底色退化
- **证据**：帧 2 里相邻两个 repo 行同色（`v2:118` 与 `v2:122` 都命中 `tr.repo:nth-of-type(odd)`）；实现用的是 `ImGuiTableFlags.RowBg`（`RepoAuditTab.cs:150-169`），插入图标行后同级行奇偶被打乱，图上那种"条目行一色 + 图标条更深"的效果需**显式压色**才会出现。
### 8. P2 — 措辞与分组的两处小残留
- 术语三套：`本机已装`（列头）/ `未装`（统计行）/ `只看本机没装的`（复选框）→ 建议统一为 `本机已装 / 本机未装`。
- 统计行第二组 `本机：未装 3 · 已停用 2` 是使用轴 + 启用轴混装且组内不可加（8+1+1+0+1+1=12 是干净的，但 3+2≠12 会诱导读者去加）→ 建议 `本机：已装 9 · 未装 3 ｜ 另：已停用 2`。顺带：`未检查` 进健康度分桶只在"没扫完"时非零（`RepoScanner.cs:105-137` 每条都会被写成非 Unknown），与 可用/死链 不同源，写在同一组要小心。
### 9. P2 — `只看本机没装的` 是筛选，却和显示开关并排、离筛选组两行远，且无 tooltip
- **证据**：`v2:87`（复选框）vs `v2:90/136/174`（`全选当前（5）`）——它实际会改变"全选当前"的范围，而"筛选 → 全选当前 → 删除"正是上轮担心误删的那条动线。
- **最小修法**：给它一条 tooltip：`只显示本机未装过插件的库（会同时改变「全选当前」的范围）`。
