## 1. design-sense（审美 / 苹果 × 编辑风底线）

结论：整体节奏已对齐「插件汉化」（40px 图标 + 三行文字块 + 右栏操作），但**文字密度违反「留白让位于内容」**。

- P1 **顶部两行说明 + 工具栏 + 投稿块 = 列表之前四层**：纵向留给内容的空间被吃掉。→ 已修：说明保持两行但压短；工具栏拆两行；投稿区默认收起。
- P1 **工具栏单行放不下时不是优雅降级而是压字/溢出**（还原图帧 3 可见）：→ 已修：搜索/排序一行、筛选/计数一行。
- P2 **层级靠颜色明度**：已符合（灰字辅助、标题默认色、单一强调橙 + 蓝/绿按钮）。
- P2 **8pt 网格**：ImGui 默认间距体系内已对齐；行高 ~52px 稳定。
- 保持：中性色打底、无边框卡片、图标尺寸与插件汉化一致。

## 3. accessibility-precheck（无障碍/可读性）

- **对比度**：`Muted` #A6A6A6 on #191919 ≈ 7.4:1，`Warn`/`Bad`/`Good` 都在 4.5:1 以上；合格。
- P2 **已赞按钮的禁用态太淡**（ImGui 默认 DisabledAlpha 0.6 会把文字压到接近背景）→ 已修：局部 0.75。
- **命中目标**：行高 ≥52px、行内按钮高度正常；达标。
- **不只靠颜色**：`[官方]/[已在库]` 是文字标签；`*` 是符号标记；统计不可用是文字 + tooltip；达标。
- **键盘/手柄导航**：整行是 `Selectable`（可聚焦），右栏按钮可聚焦；展开/收起与按钮都能用导航键到达。
- **仅 tooltip 承载的信息**（排序语义、推荐定义、♥ 顺序）：对鼠标用户足够；对纯键盘用户 tooltip 不可达——已知限制，游戏内 UI 接受（已在术语报告记录）。

## 4. wireframe-critic（布局批评）

- **主操作不明确**：一行里 ♥（社交）、加库（功能）、整行展开（信息）三个动作权重相近。→ 已修：加库=蓝主色、启用=绿、♥ 保持中性；展开靠箭头 + 整行命中。
- **右栏只有两个槽**：与插件汉化（最多四槽）相比更清爽；按钮贴右缘（左列自适应）。
- **投稿区**：功能上是低频动作，却占住列表上方一整块。→ 已修：默认收起，有投稿/消息时自动展开。
- **空态**：筛选无结果、索引不可用、统计降级各有单独一行，不互相吞。

## 5. failure-path-audit（失败路径）

| 路径 | 行为 | 是否达标 |
|---|---|---|
| 中继未部署 v8 / 不可达 | `/plugin-stats` 无 `week` → 统计降级；点赞 POST 失败 → 排队重试；页面给「统计暂不可用」 | ✅ |
| 点赞上报失败 | 本机已记（一周内按钮仍变灰）、`*` 标记未同步、每 15s 重试一条；不谎报成功 | ✅ |
| 加库失败 | 沿用插件侧备份/错误信息，状态行显示；不静默 | ✅ |
| 启用失败 | `Repos.SetEnabled` 失败路径沿用仓库体检实现；状态行给结果 | ✅ |
| 投稿抓取失败/非仓库/空仓库/无有效条目 | 本机打回并给具体原因，不发送；输入保留 | ✅ |
| 投稿 POST 失败 | 「地址没丢，网络好了再点一次」，输入保留 | ✅ |
| 云端复核失败（罕见） | `repo-inbox.yml` 记进 `repo-rejected/` + 通知维护者；无玩家身份可回 | ✅（设计如此） |
| 索引不可用（卫月改内部字段） | 页内一行 + 「重试」按钮 | ✅ |
| 旧词表（无 Repo 字段） | 「来源未知」，无加库按钮；搜索/排序正常 | ✅ |
| 状态文件写盘失败 | 静默忽略，内存态继续（重启后丢待重试） | ⚠️ 已知限制，记录 |

## 6. state-model（状态模型）

- 行状态矩阵：`官方 / 未加入 / 已启用 / 已停用` × `未赞 / 本周已赞 / 未同步` × `未投稿 / 等收录 / 已收录`；UI 均有一一对应的标签或按钮（见术语报告第 3 节）。
- 转移触发点都有反馈：加库→状态行 + `[已在库]`/按钮消失；点赞→按钮变灰（本地立即）+ `*`（未同步）→ 重试清理；投稿→「检测中…」→ 打回/已投稿；收录→「等收录」计数减少（词表更新后）。
- P2 唯一缺口：状态存储写盘失败无提示（低概率，已记录）。

## 7. cognitive-walkthrough（任务走查）

1. **用中文找插件 → 加库**：打开插件发现 → 搜「钓鱼」→ 命中 MissFisher（搜译文生效）→ 点行展开 → 看详情/库链 → 点「加库」（蓝）→ 状态行确认、行标变 `[已在库]`、推荐数 +1（后台）。**无阻断**。
2. **投稿一条坏地址**：展开「投稿插件库」→ 粘贴 → 投稿 → 「检测中…」→ 「打回：取不到这个地址…」；输入保留可改。**无阻断**。
3. **找本周热门/新插件**：默认「每周点赞排行」；切「最新更新」验证日期正确（毫秒值已归一）；切「随机」+「换一批」看到顺序真的变化。**无阻断**（随机/最新更新两处 bug 已修）。

## 8. information-architecture

- 页签名「插件发现」与「插件汉化 / 简介汉化」区分清楚：发现=浏览/收录，汉化=翻译产出。
- 投稿属于「内容生产」，放在发现页顶部并可折叠——信息架构成立（用户原话：发现页要能投稿）。
- 主窗口副标题过期（已修复）。
- 计数放筛选行、状态结果放页底，符合既有四个页签的节奏。

## 已落地的修复（v1.3.0.39）

1. 「最新更新」排序错乱 / 日期转换会抛：`LastUpdate` 毫秒与 1970 垃圾值在 pipeline 与插件两侧都做归一化（`unix_seconds` / `NormalizeUpdated`），表已重生成（1533 条有效、最新 2026-10-06）。
2. 「随机」的「换一批」无效：乱序键改成真随机值（原来按当前列表顺序发号，顺序根本不变）。
3. 工具栏拆两行、投稿区默认收起、顶部文案压缩；统计失败提示缩为「统计暂不可用」+ tooltip。
4. 点赞本地周判定用北京时间 ISO 周（中继没部署也能正确变灰）+ 未同步 `*` 标记 + 禁用态 0.75 透明度。
5. 「撤回添加」回归（单条加库也能反悔）；加库/启用接上跨页按钮语义（蓝/绿）。
6. 顶部/错误/术语一批文案修正（「拦住自动刷新」、条件库、云端语料、云端收录等）。
7. 列表虚拟化行高：给 clipper 传实测卡片行高，滚动范围不再偏 2–3 倍。
