## 1. 任务流逐步走查（透镜 B 主表）
| 步骤 | 用户此刻要回答的问题 | 界面能否直接回答 | 额外注意力成本 | 犹豫/犯错点（证据锚点） |
|---|---|---|---|---|
| **T0 打开页面** | 这页现在什么状态？有没有我上次留下的摊子？ | 部分（统计行 + 上次体检时间 + 撤回标签给了答案） | 中 | 全页最宽、最显眼的控件是「撤回上次操作（删除 84 个）」。用户第一眼读到「删除 84 个」，而统计说「共 1241 个」——他会去核对 1241 是否已经少了 84 个。数字之间没有因果关系说明。 |
| **T1 扫描** | 扫哪些库？含不含停用的？能中途停吗？ | 能（`[开始体检]` + `☑包含已停用的库`） | 低 | 「包含已停用的库」外观是普通复选框，实际是**存盘配置**（`:79 SaveConfig`），用户会以为只是本次扫描的临时开关；下次打开发现还勾着，会怀疑"默认值被我改了"。 |
| **T2 读结果** | 一共多少？坏了多少？比上次好还是坏？ | 部分（有总数+分类+上次时间；**没有与上次的差异**，没有"上次是多少"） | 中 | 同一组数字被说两遍（统计行 vs 状态行「体检完成：死链 85 · 内容不合规 2 · 连接失败 3」），用户会花时间确认它俩是不是一回事；「连接失败 3」是**灰色**的，读起来像"不用管"。 |
| **T3 筛选** | 我该先只看哪一类？「有问题的」和「死链 + 内容不合规」差在哪？我勾了"包含已停用"为什么还是看不到停用的库？ | **不能**（选项之间没有包含关系提示，也没有"筛出多少行"的预览） | 高（要试 3-4 个选项才知道差别） | 过滤器行 5 个 radio：「有问题的」实际 = 死链+内容不合规+连接失败+Blocked（`:351`+`RepoScanner.cs:46-47`），「死链 + 内容不合规」是它的**子集**却同级并列；「连接失败」无法单独筛选。 |
| **T4 勾选** | 现在选中了哪几条？切换筛选后勾选还在吗？"全选问题项"作用于哪些？ | 部分（按钮上有 `（3）`，但没有"已选 / 总范围"，没有行数） | 高 | 三个入口（`全选问题项`、`清空选择`、表头复选框）语义不同却并排/分离摆放。用户极可能以为"全选问题项"只作用于**当前视图**，实际它遍历全部 items 忽略滤镜（`:122-131`）——在「可用」视图下点它，屏幕上零变化，实际选中 90 行。 |
| **T5 停用/删除** | 这一下会动几条？能撤吗？ | 部分（按钮带计数；删除有弹窗，但**这张图没画弹窗**） | 中 | 「停用所选（3）」与「删除所选（3）…」相邻 8px、同尺寸、只靠底色分；「删除所选（3）」右边紧跟「撤回上次操作（**删除 84 个**）」，两个带"删除"字样的控件同排。停用**没有**确认（`:263-272` 直接执行并触发 reload）。 |
| **T6 撤回** | 我撤的是哪一次？撤完列表回到哪一步？ | 部分（标签只有动作+数量；撤完只有一行状态行文字） | 中高 | `UndoRecord.Describe()` 只输出"删除 84 个仓库"（`Configuration.cs:55-56`）：无时间、无备份文件名、无样本 URL。撤回后列表按当前配置重建，**被恢复的行没有任何高亮或定位**（`RefreshFromLive`），用户无法确认"东西回来了"。 |

## 3. 透镜 B 重点问题逐条回答
**a) 过滤器 ↔ 统计 ↔ 表格的联动**
困惑度：高。三个具体断点：
1. 图里「有问题的」选中却有"可用"行（N1）——联动信任直接归零；
2. 「有问题的」的真实含义（死链+内容不合规+连接失败+拒绝访问，`:351`）与旁边并列的「死链 + 内容不合规」不是同一层级（N22）；
3. 统计数字与过滤器选项**不是同一套分类**：统计有"连接失败"这一格，过滤器却没有对应选项；过滤器的"可用"包含"空仓库"（`:350`），统计的"可用 1151"是 `Ok` 计数——两边切片不同（静态图无法验证，需实机对数）。
最小改法：统计数字可点即筛选 + 过滤器行显示"结果 N 行"。
**b)「全选问题项」是否多余/误导**
不多余，但**当前形态是危险的**。三条理由：
- 扫描完成后问题项已经自动勾选，用户没有清空过时点它是 no-op，且**无任何反馈**（无 toast、无计数变化），用户会重复点击；
- 它跨过滤器作用于全部问题项（`:122-131`），在「可用」视图下点它屏幕零变化但实际选中 90 行；
- 「删除所选（3）…」在它正下方两行处，而"停用"没有二次确认。
建议：把「全选问题项 / 清空选择」升级为**表头三态复选框 + 过滤器行右端的"已选 3 / 共 90"**，按钮文案写成作用域明确的 `选中全部 90 个问题项（含未显示的）`。表头复选框目前**只存在于这张图里**（实现没有，`:169,:173`），要么补齐实现（必须三态），要么从图上删掉——现在这种"有复选框但状态与行不符（表头选中、仅 3/7 行勾选）"的状态是最坏的组合。
**c) 无选择时置灰 + 提示语是否足够**
不够，三点：
1. 这张图**没有画置灰态**（按钮是亮的、带计数 3），所以图本身没有验证该状态；
2. 实现里提示只有 hover tooltip 一句"先在下面的列表里勾选要处理的仓库"（`:256-259`、`:283-286`），disabled 元素能否 hover 在不同 ImGui 版本/主题下表现不一致，很可能是**用户根本看不到**；
3. "无选择"这个状态在实现里几乎只会出现在用户刚点过**「清空选择」**之后（因为扫描完默认已勾选 90 个），此时正确的提示是"已清空，可点『选中全部问题项』恢复"，而不是"先去下面勾选"——提示语和触发场景不匹配。
最小改法：常驻一句 `已选 0 / 共 90`，禁用原因作为该行的文字而不是 tooltip。
**d) 红色删除与安全按钮的视觉分隔是否足够**
不够。证据：两按钮相邻约 8px、同尺寸同圆角同形状，分隔符却在删除**之后**（把危险与安全划成一组）；深红 `#6b2a2a` 叠在 `#191919` 上对比度约 2.5–3:1，低于阈值；同一行右侧还并列"删除 84 个"的字样。另外，上下两行的按钮在水平方向有重叠带（第一行右端是「全选问题项 / 清空选择」，第二行右半区是「撤回上次操作 / 打开备份目录」），快速连点会落到改变状态或弹资源管理器的控件上（具体落点依实际窗口宽度与字体，需实机确认）。
最小改法：`停用所选 │ 删除所选…`，删除按钮改亮红/加图标并固定在最右端。
**e) 撤回按钮的信息量是否恰当**
"类型 + 数量"只到及格线，不够。缺四样：时间、备份文件名、样本 URL、"还剩几步可撤回"。而且 84 这个数在页面上没有对照物——那 84 行已经不在列表里了，用户无法验证。另有一处结构性浪费：UI 只暴露 `UndoHistory[^1]`（`:304-305`），而后端存了 10 条（`Configuration.cs:107`）。
建议标签：`撤回上次操作（删除 84 · 20:12）`；tooltip：`备份：repos-20260916-2012.json\n样本：…/yimo0908/…、…/Nexaii/…\n剩余可撤回：9 步`。
**f) 表头列信息密度与截断策略**
分配不合理：
- 状态列给了 150px（实现 118px），而最长内容"可用 · 已停用"约 90px → 浪费约 30-60px；
- 「首次记录」128px，图上 7 行里 6 行是 `—` → **约 18% 的列表宽度在放空值**；
- 地址列吃掉剩下的约 360px，而用户真正要分辨的是 `owner/repo`（GitHub 长 URL 里最有信息量的段落），图上却被压缩到只剩尾部；
- 更糟的是这张图用的是"前省略"（`…/raw.githubusercontent.com/...`），而实现是"头…尾"（`UiHelpers.cs:41-52`）。前省略会**吃掉诊断信息**：第 2 行"内容不合规"的不合规证据恰好是 `/blob/`（blob 页面不是合法仓库文件），前省略后 `github.com` 被换成 `…`，用户看不出为什么它不合规。
建议：地址列主行为 `owner/repo`（+ 域名小字），完整 URL 放 tooltip 并支持右键复制；「首次记录」列在无数据时隐藏或降级为地址列尾部灰色小字。另外 ImGui 的 `TextUnformatted` 文本**不可选中复制**，这个页面的用户必然想拿死链去浏览器验证——必须给复制入口。

## 4. 操作按钮条：上方 vs 下方
**结论：放列表正上方更好**，但"撤回"不该留在这一条里。
| 维度 | 上方（现状） | 下方 |
|---|---|---|
| 邻近性 | 与勾选动作的视线距离是"列表顶部→列表内部"，中/短列表下最短；但 1241 行时用户鼠标常在列表中部 | 与列表尾部勾选邻近；鼠标停在列表底部时反而更近 |
| 可发现性 | 高：与过滤器、选择计数同区，进入页面第一屏就看到 | 低：ImGui 里虽然也在滚动区外，但用户会先看上方，容易整场忽略 |
| 误触 | 与过滤器行右侧控件在垂直方向有重叠带；红色按钮与"停用"仅隔 8px | **更高**：长列表用户鼠标长期停在列表下缘，红色按钮就在旁边，滚动/点击惯性直接命中 |
| 长列表 | 工具条不随滚动移动，位置稳定 | 同样不滚动，但视觉上"沉底"，与"批量选择"的心理模型脱节 |
| 反馈距离 | 操作结果写在下方的状态行 → 动作与反馈跨了一整条列表 | 动作与状态行紧邻 |
**我最推荐的布局（这是问题的核心答案）**：
```
┌ 标题栏 / 标签页
├ 说明（折叠，首次引导）
├ 扫描行： [开始体检] [☑ 扫描范围含已停用]        进度条 312/1241（仅扫描中）
├ 统计+撤回行： 共 1241 · 可用 1151 · 死链 85 · 内容不合规 2 · 连接失败 3
│                                  [撤回上次操作（删除 84 · 20:12）] [备份目录]   ← 常驻，右侧固定
├ 筛选行： 主筛选(radio) | 问题类型(复选) │ 结果 90 行 · 已选 3 / 90
├ 操作条（紧贴表格上缘）： [停用所选（3）] │ [删除所选（3）…]                    ← 危险在最右，有分隔
└ 表格（表头三态复选框、排序、搜索、右键菜单）
```
要点：① 撤回从操作条拆出，固定到统计行右端——任务硬约束"任何时候可见"由它保证，且远离红色按钮；② 停用/删除留在列表上方、紧贴表格；③ 破坏按钮之间加分隔与间距。

| 排名 | 布局 | 说明 | 优点 | 缺点 |
|---|---|---|---|---|

## 5. 综合结论
**最严重的 5 个问题**
1. **一段 3 秒操作可以停用 90 个仓库**：默认勾选把"连接失败"也算进去（N19，`:421`+`RepoScanner.cs:46-47`）、「全选问题项」跨视图生效且无反馈（N16）、停用无二次确认（N15）。三者叠加，加上唯一的防线是"撤回"。
2. **页面唯一的两个控制面（"显示"筛选与"已选 N"）不可信**：图中过滤器选中"有问题的"却显示"可用"行（N1）；状态行永远写着"问题项已自动勾选"（N2）；没有"结果 N 行 / 已选 N 共 M"（N3）。用户在这里的默认反应是"这页在说哪个才是真的"。
3. **破坏按钮与安全按钮分组倒置、视觉无分隔**（N13/N14/N17）：8px 相邻、同形状、仅靠低对比深红区分，且与"删除 84 个"字样同排。
4. **1241 行任务在 700×620 里不可完成**：列表可视仅 7 行（N24），没有搜索、没有排序、没有区间选择、URL 不能复制（N20/N18）。用户实际花费会从"几分钟"变成"滚动几百屏"。
5. **"已停用"的双层语义 + 状态列混装两个维度**（N7/N23）：勾了"包含已停用"看不到停用的库；"可用 · 已停用"用同一个绿色，用户分不清它在报告健康还是报告启用状态。
**最容易改的 3 个（quick wins）**
1. **撤回标签补时间 + 从操作条移到统计行右端**：改一处格式化（`Configuration.cs:55-56`）与一次位置调整；同时解决"常驻可见"的硬约束与"红色按钮旁边是撤销"的分组错误。
2. **状态行静态文案改动态计数**：把 `（问题项已自动勾选）`（`:467`）换成 `已选 {selected.Count} / 共 {problemCount} 个问题项`，并删掉重复的统计行（N2/N5）——约 5 行代码，直接消灭截图里最刺眼的矛盾。
3. **操作条加分隔与间距 + 地址列改中间省略**：`停用所选 │ 删除所选…`（`RepoAuditTab.cs:263-300`）降低误点；`UiHelpers.Shorten` 改成保留 host+owner/repo，并让 URL 可复制（N17/N18/截断策略）。
（附赠，同样便宜：过滤器行加"结果 N 行"；统计数字做成可点 chip。）
**需要结构性重构的问题**
- **S1 纵向空间重排**：说明折叠、统计并入筛选行、状态行与撤回合并。列表可视行数从 7 提到 12-14，是所有其它改动的前提。
- **S2 状态模型**：把"健康"与"启用"拆成两个视觉通道（状态列只放健康；"已停用"整行降透明度 + 行尾灰标签），并统一"扫描范围/显示过滤"的命名，消除双层"已停用"。
- **S3 选择模型**：表头三态复选框 + 显式作用域（当前筛选 / 全部问题项）+ 已选计数 + Shift 区间选择 + 重扫/切筛选时的选择保留规则（当前是静默清空，`:399`）。
- **S4 安全模型**：默认只勾选"死链 + 内容不合规"；删除确认弹窗保留并补"停用"的回执；把已存在的 10 条 `UndoHistory`（`Configuration.cs:107`）做成"操作历史/回收站"面板；撤回后被恢复的行高亮并滚动定位。
- **S5 长列表定位**：搜索框 + 表头排序 + 行级右键（复制 URL / 浏览器打开 / 单行停用 / 单行删除）。
**无法从静态图判断、需要实机确认的项**（本评审未认定对错）：悬停提示是否真的显示、滚动条外观、键盘/焦点行为、界面字体缩放后的换行与裁切、删除确认弹窗文案与默认焦点、禁用态外观、扫描中状态、空历史（无撤回记录）状态、错误状态行呈现、撤回后是否有高亮。
**Merge verdict: BLOCK** —— 设计稿本身的信息架构方向可用，但必须先澄清 N1（图与实现自相矛盾）、并把 N2/N16/N17 三项修掉（前两项还同时是真实实现缺陷，见 `RepoAuditTab.cs:467`、`:122-131`、`:263-300`），否则 90 个仓库级别的误操作与"界面在撒谎"会被原样带进实现。
