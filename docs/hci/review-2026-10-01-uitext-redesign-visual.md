# FireGaze「插件汉化」改版 视觉盲评（还原图）

- 评审对象：`Resources/ui-mockup-uitext-list.png`（4 帧）、`Resources/ui-mockup-uitext-editor.png`（2 帧，编辑校对 + 翻译设置）
- 评审方式：**只看 PNG 与 HTML/CSS**，未读任何实现代码（盲评）；评分基准 = `design-sense`（Apple HIG × Editorial）＋项目既有 UI 约定
- 说明：还原图是 HTML/CSS，实机是 ImGui。凡"In ImGui 里做不到"的条目一律标注，并给替代方案。
- 评审日期：2026-10-01

---

## ① 一句话总评

骨架是对的——列表就是"图标 + 标题 + 一行简介 + 状态 + 一个主操作"，展开才给详情，按钮数量控制得干净；但**"状态"与"动作"这两件最该一眼看清的东西没有形成可竖扫的一列**：状态徽标的位置随文字长度浮动、还原按钮反而比更新按钮更抢眼、同一个蓝色按钮在三个窗口里代表三种动作——把这三处收束好，这页就从"能用"变成"好用"。

---

## ② 逐条视觉问题

> 格式：编号 · 严重度 · 位置 → 问题 / 依据守则 → 改法（含具体数值）

### A. 列表页（`ui-mockup-uitext-list`，帧 1–4）

**V1 · P1 · 帧 1 第 1–2 行动作区**
- 问题：**按钮视觉权重反了。**「更新汉化」用了 `btn.plain`（底色 `#2a2a2a`、边框 `#4a4a4a`），而「还原原文」用的是默认 `.btn`（底色 `#3c3c3c`、边框 `#565656`）——**回退操作比前进操作更亮、更凸**。截图里"还原原文"确实比"更新汉化"更显眼，眼睛先跳到它上面。
- 依据：design-sense 一·3「深度：用层级建立视觉次序」；本次评审要求"危险操作不抢眼"。
- 改法：已汉化的行（可维护但非紧急）——「更新汉化」用普通按钮 `#3c3c3c` / 边框 `#565656`；「还原原文」降级为**文字按钮**（无底色、无色边框、文字 `#a6a6a6`，hover 才出 `#2a2a2a` 底），并与主操作拉开 ≥12px 的距离。ImGui 落地：`PushStyleColor(ImGuiCol_Button, ImVec4(0,0,0,0))` + 文字色 muted + `ButtonHovered` 给 `#2a2a2a`。

**V2 · P1 · 帧 1 每一行的状态徽标**
- 问题：**状态不是一列。** 徽标跟在「内部名 · 版本」后面行内排布，x 位置随前面文字长度浮动（"Globetrotter · v1.2.17" 与 "SimpleTweaksPlugin · v1.15.0.7" 的徽标起点差了一截）；同时它是全行**最小字号（12px）**、与版本号同色同重量。198 个插件的列表里，用户最先要回答的问题是"哪些还没汉化"，而现在必须逐行横读才能找到答案。
- 依据：design-sense 一·1「清晰：每个元素都有明确目的」、一·3「层级用字号/字重/透明度」。
- 改法：把徽标提到 meta 行**行首**（与插件名左对齐，形成一条竖线），或做成固定列右对齐到动作按钮左侧；字号 12 → **13px**；「内部名 · 版本」保持 12px `#8b8b8b`。功能分工会立刻变清楚：一行 = 状态（可扫）→ 名字 → 动作。

**V3 · P2 · 帧 1 三个动词并存**
- 问题：同一个按钮位置出现 **一键汉化 / 应用汉化 / 更新汉化** 三种说法，差别只能靠顶部那句 47 字的说明去理解（"翻译、写入、重载一次完成"）；「应用汉化」与「一键汉化」的颜色、尺寸完全一样，用户无法就地判断点了会发生什么（会不会重新花时间翻译？会不会覆盖我改过的译文？）。
- 依据：守则"一致性"；项目既有约定「一个概念一个词」。
- 改法：收敛成两档并在按钮上就地说明——含翻译的写「一键汉化」，只应用的写「应用汉化」，两者都加 tooltip 一行（例：「会翻译 190 条 + 写入 + 重载插件」／「只应用已有 65 条译文，不再翻译」）。「更新汉化」并入「一键汉化」，不要第三个词。

**V4 · P2 · 帧 4 第 2 行（失败态）**
- 问题：**失败用了两套色。** 徽标是 `.badge.warn`（黄 `#f2bf59` / 底 `#2c271c`），下面那行说明是 `.steps.bad`（红 `#f27373`）。同一个事件既黄又红，用户会读成"警告"而不是"出错了"。
- 依据：守则"色彩语义一致"；本次评审要求"完成绿 / 进行中蓝 / 警告黄 / 失败红 是否一致"。
- 改法：失败徽标改红系（文字 `#f27373`、底 `#2c1e1e`、边框 `#6b3a3a`），黄只留给"需要处理 / 部分完成"。四处状态色一一对应，不再有交叉。

**V5 · P2 · 帧 1 「官方」标签**
- 问题：「官方」与状态徽标是**同一种形状**（12px + 1px 描边 + 3px 圆角的小方块），只差颜色。形状相同 → 语义拉平，状态徽标的信息量被稀释。
- 依据：守则"深度：用层级而非边框"。
- 改法：官方标签去掉边框，改成纯文本 `#8b8b8b` 12px（或换成"药丸形 vs 方形"的形状区分）；颜色/描边块只留给状态。

**V6 · P2 · 帧 1 图标列**
- 问题：字母图标块有四种装饰底色（蓝 `#3b4a63`、棕 `#5a4632`、绿 `#3f5240`、紫 `#584050`），其中**绿、黄系与状态色（已汉化绿 / 警告黄）撞车**——Orbwalker 的绿色图标块和"已汉化"的绿色徽标在同一行里互相干扰。这些底色没有任何语义，只是装饰。
- 依据：守则一·4「单一强调色」、一·1「避免装饰性噪音」。
- 改法：没有真实图标时的字母块统一用**中性单色**（底 `#2a3242`、字母 `#cfe0ff`），让"界面里的颜色只表示状态"。有真实插件图标时直接显示真图（本次还原图是占位，实机以真图为准，见文末 ImGui 注）。

**V7 · P2 · 帧 2 展开区正文**
- 问题：「Orbwalker is a movement locking plugin…」与「普通用户看这里就够：点上面的「应用汉化」…」**同字号（13px）、同颜色（`#c9c9c9`）**，中间只隔一个空行，视觉上糊成一段；而后者才是本产品想说的话。
- 依据：守则"层级用字号/字重/透明度表达"。
- 改法：引导句单独成形——12px / `#a6a6a6` + 左侧 2px 竖线（或浅底块 `#232323`，左右各 8px 内边距），并**放到英文简介之前**；作者简介保持 13px `#c9c9c9`。

**V8 · P3 · 帧 2 作者简介行宽**
- 问题：展开区正文可用宽度 ≈ 710px，13px 英文一行可容纳约 95–110 个字符，远超舒适行宽。
- 依据：design-sense 三「正文行高 1.5–1.7」的配套常识（行宽 60–75 字符）。
- 改法：把正文换行宽度限制在 **≈600px**（ImGui：`PushTextWrapPos(GetCursorPosX() + 600f)`），或把正文字号提到 14px、行高 1.6。

**V9 · P3 · 帧 2 统计行**
- 问题：一行堆了 5 个数字，且**用了两种分隔符**（`·` 与全角 `｜`）：`候选 78 条 · 已翻 65 条 · 未翻 13 条 · 灰名单 7 条 · 标记不翻 0 条 ｜ 补丁：未应用（原始文件已备份）`；其中"标记不翻 0 条"是恒零项，每次都占位。
- 依据：守则"一致性 / 细节"。该行还是 13px muted，13 个数字读起来没有重点。
- 改法：只留可行动的三个数——`候选 78 · 已翻 65 · 未翻 13`（"未翻 >0" 时用 `#9ec2f0` 提一下），其余进 tooltip；分隔符统一 `·`；"补丁：未应用"升级成与行上徽标一致的 12px 小徽标，不再混在数字串里。

**V10 · P3 · 帧 3 进度条 / 帧 4 汇总计数**
- 问题：还原图自身数据不自洽。① 帧 3 进度条 CSS `inset: 0 42% 0 0` = 填充 **58%**，但文字是 `137 / 255` = **53.7%**；② 帧 4 里 BOCCHI 已变"已汉化 255 处"，右上角仍是 `已装 198 · 已汉化 12`，应为 13。
- 依据：项目既有还原图纪律「图必须与实现同序同数（计数/行数对得上）」。
- 改法：进度条宽度按计数算（137/255 → 右 inset 46.3%）；帧 4 的汇总数字同步 +1。

**V11 · P3 · 帧 1 展开面板归属感**
- 问题：展开行 `#202020`、展开面板 `#1f1f1f`、列表底 `#1c1c1c`，三者只差 3 个色阶，面板看起来像"另一段内容"而不是"这一行的展开"。
- 依据：守则"深度"。
- 改法：展开面板左侧加 **2px 强调色竖线**（`#8cbfff` 或 `#4b6f9c`，从面板顶到底），或把面板底色提到 `#232323` 拉开档位。

**V12 · P3 · 帧 1 顶部 chrome**
- 问题：标题栏 `FireGaze` ＋ 品牌行 `FireGaze | 卫月插件库工具箱 · 汉化 / 体检 / 拦住自动刷新` ＋ 页签，连续三条横带；品牌行副标题列举的三个功能与页签内容重复，纯占高度（780×560 的窗口里，列表只能露出 5 行）。
- 依据：守则一·2「界面让位于内容」。
- 改法：删掉副标题（或只在首次使用/关于页出现），品牌行退化为一行小字或直接并入标题栏。

**V13 · P3 · 页签命名**
- 问题：「简介汉化」与「插件汉化」两个页签并排，只差两个字；前者汉化的是**插件简介**（列表里那行描述），后者汉化的是**插件界面文本**——用户第一眼会以为它们是同一件事的两个入口。
- 依据：守则一·1「清晰」。
- 改法：新页签改名 **「界面汉化」**（或"界面文本"），与"简介汉化"在名字上就能区分；若两者其实是一件事的两个阶段，就合并成一个页签的两个分区。

**V14 · P3 · 帧 4 第 3 行（无可翻译文本）**
- 正面：这一行**不放任何假按钮**，只留展开箭头——完全符合"去掉不必要的按钮"。（列入优点，见 ④。）

### B. 编辑校对窗（`ui-mockup-uitext-editor` 帧 1）

**V15 · P2 · 工具栏主按钮**
- 问题：编辑窗的主色按钮是「批量翻译未翻 (13)」，而列表页的主色按钮是「一键汉化 / 应用汉化」——**同一个蓝色，在三个窗口里代表三种动作**。读者没法建立"蓝色 = 完成这件事"的直觉。
- 依据：守则一·4「一致性」。
- 改法：编辑窗把**「应用汉化」提为主色**（与列表页同一动作、同一个颜色），把「批量翻译未翻（13）」降为普通按钮，用"未翻 13 条"的计数色（`#9ec2f0`）提示还有活干。

**V16 · P2 · 译文列颜色**
- 问题：译文列 65/78 行全部是 `#cfe0ff` 浅蓝——**强调色被整列稀释**，与蓝色主按钮互相抢注意力；蓝色不再意味着"重要/可交互"。
- 依据：守则一·4「单一强调色（中性色打底）」。
- 改法：译文正文用 `#e4e4e4`；蓝色只保留给**本次会话改过的单元格**（"我动过这里"）或链接；未翻仍是 muted `#a6a6a6`。

**V17 · P2 · 标题栏**
- 问题：标题写成 `插件汉化 — Orbwalker###FireGazeUITextEditor`。ImGui 会把 `###` 之后的部分当窗口 ID **隐藏**，用户永远看不到它——还原图把实现细节画进了用户界面，实现者若照抄会画出错误标题。
- 依据：还原图纪律「图必须与实现同序同数」。
- 改法：标题只写 `插件汉化 — Orbwalker`；窗口 ID 作为图注/注释写在画面外。

**V18 · P3 · 表格首列（✔ / ⚠ / ·）**
- 问题：首列有 34px 宽却没有表头、也没有图例，颜色和图形是唯一语义；`⚠` 那一行（`Casters → 法系`）用户不知道需要他做什么。
- 依据：守则一·1「清晰」；一般表格可读性惯例。
- 改法：列头写「状态」（12px muted）；`⚠` 加 tooltip「疑似术语/键名，建议人工确认」；或首行放一行 12px 图例。

**V19 · P3 · 禁用按钮**
- 问题：「还原原文」以整体 `opacity: .45` 呈现，文字与底对比降到约 **3.5:1**（低于 4.5），且没有说明为什么不可用（上一行状态明明写着"已写入 65 处译文"，用户会觉得该能点）。
- 依据：项目既有约定「禁用态不要用整体透明度压字色」。
- 改法：显式给禁用文字色 `#7a7a7a`（底/边框保持），并加 tooltip「还没有已写入的补丁」。

**V20 · P3 · 状态行「自动保存」**
- 问题：`通道：deepseek · 自动保存`——"自动保存"很容易被读成"改动已应用进插件"，实际它只保存译文草稿（应用要另外点按钮）。
- 依据：项目既有约定「关键状态常驻且不含糊」。
- 改法：改成 `译文改动已自动保存 · 应用请点「应用汉化」`（13px muted），把"保存了什么"说死。

**V21 · P3 · 按钮计数括号**
- 问题：`批量翻译未翻 (13)` 用半角括号，项目既有按钮约定是**全角「（N）」**（如「删除勾选（N）」）。
- 依据：项目既有 UI 约定「同一排括号数字语义统一」。
- 改法：统一 `批量翻译未翻（13）`；并且括号数字只用于"作用于 N 个对象"的批量操作。

**V22 · P3 · 可编辑单元格的虚线下划线**
- 问题：`border-bottom: 1px dashed #5a5a5a` 在浅色文字下方，视觉上接近浏览器"拼写检查"的下划线暗示（"这里有问题"），而现在 65 行都是这个状态。
- 依据：守则"细节：符号要有一致的含义"。
- 改法：二选一——① 只在 hover/focus 时出现输入框或描边（推荐，ImGui 里就是 hover 时换成 `InputText`）；② 保留虚线但在表头加 tooltip「双击编辑」。

**V23 · P3 · 搜索框位置**
- 问题：列表页搜索框在工具栏**最左**，编辑窗搜索框在筛选行**最右**（`margin-left:auto`）；同一类控件在两个窗口里位置相反。
- 依据：守则一·4「一致性」。
- 改法：统一放到筛选行左端（与列表页一致），右侧留给计数。

### C. 翻译设置窗（同张图 帧 3）

**V24 · P2 · 输入框颜色**
- 问题：`.field { color: var(--muted) }` ——**所有输入框的文字都是 `#a6a6a6`**（占位色）。于是"接口地址"里那串 `https://api.deepseek.com/v1` 到底是**已配置的值**还是**灰字提示**，用户分不出来；同理 key 那一格"已保存（sk-…4f2a），要换就粘贴新的"也读不出是状态还是提示。这是一个"配置到底生效没有"的信任问题。
- 依据：守则一·1「清晰」；一·4「一致性（同一颜色同一含义）」。
- 改法：有值 → 正文色 `#e4e4e4`；空值/占位 → `#a6a6a6`。key 的"已保存"不要只写在括号里：用「已保存 · sk-…4f2a」+ 行尾一个 12px 绿点或"已配置"小徽标。

**V25 · P2 · 「保存 key」与「清除」同权 + 整窗没有主操作**
- 问题：`保存 key`（灰）与 `清除`（灰）并排且完全同形，**清除一个已保存的 key 是破坏性操作却没有任何弱化**；同时整个设置窗里没有任何一个主色按钮、也没有出现强调色（选中态是纯白 `#d8d8d8`），页面没有"做完这件事"的终点。
- 依据：守则一·3「深度」；评审要求"危险操作不抢眼"。
- 改法：`保存 key` 升为主按钮（同列表页 `#2f4a6d` / 边框 `#4b6f9c`）；`清除` 降为文字按钮并加二次确认；单选的选中态用强调色（`#8cbfff` 的小圆点或描边），不要用与正文同色的纯白。

**V26 · P2 · 层级反转：选项标签 16px > 分节标题 14px**
- 问题：`.section .h { font-size:14px }`，而下面的选项文字（`批量翻译时连灰名单一起翻`、`插件更新后自动重打汉化补丁`）是**裸文本继承 body 的 16px** —— 小标题比它管的条目还小。列表页工具栏的「只看第三方」同样是 16px，比旁边的按钮（14px）和说明（13px）都大。
- 依据：守则「层级用字号/字重/透明度表达」。
- 改法：所有裸文本显式声明字号——选项/复选标签 **14px**，分节标题 **15px** + 颜色 `#d0d0d0`（ImGui 不便加粗时，用字号+色差替代字重）。

**V27 · P3 · 表单标签列宽不一**
- 问题：「接口地址」是自动宽（约 56px），「大模型 API key」写死 `width:100px`，两行的输入框左边缘因此**不保证对齐**（视觉上应是一列）。
- 依据：守则一·5「细节：对齐像素级」。
- 改法：同一表单内的标签统一固定列宽（建议 100px），输入框左边缘对齐到同一 x；「模型」这种短标签放在同一行时也走同一列宽。

**V28 · P3 · 免费通道提示常驻**
- 问题：`免费通道：Google / MyMemory 按 IP 限流（…）` 在"大模型（自填 key）"被选中时仍然显示，与当前选择无关，属于无效信息。
- 依据：守则一·1「每个元素都有明确目的」。
- 改法：该提示只在选中免费通道时出现；选中大模型时换成"key 只存本机"那条（它本来就有，位置也更合理）。

**V29 · P3 · 大模型块的从属关系没有视觉表达**
- 问题：「大模型（自填 key）」是一个单选，下面的"大模型"小节（接口地址/模型/key）属于它，但两者只是上下相邻，没有缩进、竖线或底色来表明从属；选别的通道时这一块会不会变灰也看不出来。
- 依据：守则"深度 / 层级"。
- 改法：该小节整体左缩进 8–12px + 左侧 2px 竖线（或包一层 `#1c1c1c` 底），未选中时整块降到 0.5 透明度并禁用（ImGui：`BeginDisabled()`）。

**V30 · P3 · 括号**
- 问题：`大模型（自填 key）`、「免费通道…（遇到 429 会自动礼让、退避…）」、「已保存（sk-…4f2a）」——括号里塞解释，在窄窗口里把控件标签撑长。
- 依据：项目既有约定「非必要不使用括号」。
- 改法：标签写「大模型」，把"需自填 key"挪到下面一行的灰字或 tooltip；状态行里的括号改成 `·` 连接。

### D. 跨窗口一致性（两图之间）

**V31 · P3 · 窗口 chrome 两套尺寸**
- 问题：主窗口 `.osbar` 高 **28px**，设置窗 `.titlebar` 高 **26px**；字体 13px vs 13px 相同，但高度不一致。
- 依据：守则一·4「一致性」。
- 改法：统一 26px（ImGui 的标题栏高度由样式决定，两个窗口本来就该一致——这条在实机里几乎自动满足，还原图对齐即可）。

**V32 · P3 · 蓝色家族有 4 个值**
- 问题：accent `#8cbfff`（品牌/文本）、主按钮 `#2f4a6d` + 边框 `#4b6f9c`、进度条填充 `#3f6699`、信息徽标 `#9ec2f0` —— 四个蓝色各说各话。
- 依据：守则一·4「单一强调色」。
- 改法：收敛成两档 token——`accent`（文字/徽标/选中态）与 `accent-deep`（按钮底/进度填充），中间只靠明度变化；进度条直接用主按钮边框色 `#4b6f9c`，信息徽标用 accent 的 60% 亮度版本。

**V33 · P3 · 计数信息的位置不统一**
- 问题：列表页计数在工具栏右端（`已装 198 · 已汉化 12`），编辑窗计数在标题行右端（`候选 78 · 灰名单 7 · 已翻 65 · 不翻 0`），设置窗没有。
- 依据：守则一·4「一致性」。
- 改法：同一类"本页统计"固定放在窗口内容区右上角（工具栏行右端），编辑窗的计数也移下来与搜索框同一行。

**V34 · P3 · 间距节奏偏细，且脱离 8pt 网格**
- 问题：`.body gap:6px`、按钮内边距 3px、页签间隙 2px、展开区 `margin-top:6/8px` —— 节奏是**一致**的（这点很好），但全部落在 8pt 网格之外。
- 依据：守则「8pt 网格」。
- 改法：[ImGui 受限] 不用逐像素照搬：把"行与行"的呼吸感映射到 `ImGuiStyle.ItemSpacing`（建议 `8×6`），按钮内边距映射到 `FramePadding`（建议 `10×4`），只要同一类元素用同一档间距即可。**不要**把 6px 当成硬指标。

## ④ 做得好的地方

1. **展开区左内边距与列表文字左边缘像素级对齐**：行 `padding-left 10 + 图标 40 + gap 10 = 60px`，展开面板 `padding-left: 60px` —— 展开内容与插件名共用同一条左基准线，读者立刻知道它属于哪一行。这个细节很多插件都不做。
2. **状态色用得克制且语义单一**：完成绿 `#73d973`、进行中/信息蓝 `#9ec2f0`、未汉化中性灰、失败红 `#f27373`，**只出现在小徽标和一行 12–13px 说明上**，从不刷大面积背景；帧 4 三行（成功 / 失败 / 无文本）的颜色与语义一一对应，扫一眼就能分清三件事。这是本次改版最成熟的部分。
3. **"去掉不必要的按钮"落实得干净且有规则**：每行最多两个按钮（不做假的第三第四个）；帧 4 第三行（无可翻译文本）一个按钮都不给，只留展开箭头；帧 3 进行中的行只留「取消」。同时在列表页建立了可读的主次规则——**需要处理的插件才给蓝底主按钮，已汉化的行一律降级为灰按钮**，眼睛会先落到"要做的事"上。
4. **编辑表格的排版克制**：无竖线、只用 1px 底部线与行列留白分隔，`font-variant-numeric: tabular-nums` 让数字对齐——符合"用留白与层级而非边框"的取向，密度也控制在了可读范围内。

## 附：ImGui 落地注意（受限项汇总）

| 还原图里的东西 | ImGui 现实 | 处理建议 |
| --- | --- | --- |
| 3–5px 圆角、图标块渐变 | 圆角来自主题（`WindowRounding`/`FrameRounding`），渐变几乎不用 | **可忽略**；不要为还原图的圆角写死样式 |
| `box-shadow` | ImGui 基本不用阴影 | 用 `#232323` 一档底色代替阴影表达浮起 |
| `white-space: nowrap; text-overflow: ellipsis`（简介截断） | **没有原生省略号** | 用 `PushClipRect` 裁剪 + 手动按 `CalcTextSize` 二分截断补 `…`；或直接允许换到第二行 |
| `line-height: 1.4–1.55` | ImGui 无行高概念 | 用字体大小 + `ItemSpacing` 近似；正文换行用 `PushTextWrapPos` |
| `font-weight: 600`（标题/品牌） | 需要**单独加载一份 bold 字体**才能加粗 | 层级尽量只用字号 + 颜色（当前还原图已经这么做，很好）；确实要粗体就在字体图集里合并一份 |
| `font-variant-numeric: tabular-nums` | 取决于所加载字体；CJK 字体里数字通常等宽 | **可忽略** |
| 12px 中文（徽标、meta） | Dalamud 字体图集按用户字号生成，12px 中文容易发虚/糊 | 中文最小 **13px**；12px 只给纯数字/拉丁（如版本号） |
| `opacity:.45` 禁用态 | `BeginDisabled()` 就是叠 alpha，效果相同 | 接受；但要补 tooltip 说明为什么不可用（V19） |
| 主按钮 `#2f4a6d` | ImGui 按钮三态色由主题给，不写就是灰色 | 实现时**必须**显式 push：`Button #2f4a6d` / `Hovered #3a5b86` / `Active #45699a`，边框 `#6b93c4`，否则主按钮与普通按钮完全同色 |
| 悬停 / 空状态 | 还原图没有这两帧 | 建议补 1 帧（搜索无结果 / 全部已汉化）与 1 帧 hover 态，实机截图即可，不必再画 HTML |
