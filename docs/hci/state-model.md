# 插件发现 — 状态模型（state model）

对象、动作见 `conceptual-model.md`；失败路径的 UI 表现见 `failure-path-audit.md`。

## 1. 插件行（TranslationIndexEntry）

状态维度（互相独立、可叠加）：

| 维度 | 状态 | 含义 | 用户可见线索 | 进入 | 退出 |
|---|---|---|---|---|---|
| 来源 | 官方 | 来自官方主库（Dip17） | 行尾 `[官方]` | —— | —— |
| 来源 | 未加入 | 库链不在本机列表 | 右侧「加库」按钮 | —— | 加库成功 |
| 来源 | 已启用 | 库链在本机且启用 | `[已在库]`，右侧无按钮 | 加库/启用成功 | 仓库体检停用 |
| 来源 | 已停用 | 库链在本机但停用 | 右侧「启用」按钮 | 仓库体检停用 | 启用成功 |
| 来源 | 来源未知 | 旧词表没有 Repo 字段 | 来源库列 `—`，无库按钮 | 旧词表 | 词表更新 |
| 点赞 | 未赞（本周） | 本周没给该插件点过 | ♥ 可点 | 周一 00:00（北京） | 点赞 |
| 点赞 | 本周已赞 | 本机已记本周赞过 | ♥ 变灰（0.75 透明度） | 点赞（本地先记） | 下周一 |
| 点赞 | 未同步 | 上报还没成功 | ♥ 标签后 `*` | 上报失败 | 重试成功 |
| 点赞 | 计数未知 | 中继统计拉不到 | ♥ `—/—` + 统计暂不可用 | 拉取失败 | 拉取成功 |

无效转移（有意不做）：本周取消赞（v1 设计）；对官方条目加库；对同一库重复计推荐；对「来源未知」加库。

## 2. 库链

```
未加入 --加库--> 已启用 --体检停用--> 已停用 --启用--> 已启用
已启用 --撤回添加--> 未加入
```

## 3. 投稿

```
未投稿 --投稿--> 检测中 --不合格--> 打回（本机给理由，可改后重投）
检测中 --合格--> 已投稿 --云端受理--> 等收录 --词表更新--> 已收录
```

- 「检测中」的可见线索：按钮变「检测中…」。
- 「打回」：输入保留、状态行给原因。
- 「等收录」：投稿区计数行 `已投稿、等收录：N 条`；词表带上该库链后自动消失。

## 4. 统计快照

`新鲜（<10 分钟）→ 过期（下次打开/10 分钟后拉取）→ 拉取失败 → 用上次缓存/本机缓存文件`。

## 5. UI 状态覆盖检查（每状态是否有独立视觉）

| 状态 | 独立视觉 | 结论 |
|---|---|---|
| 官方 / 未加入 / 已启用 / 已停用 / 未知 | 标签 / 按钮 / `—` | ✅ |
| 未赞 / 本周已赞 / 未同步 / 计数未知 | 可点 / 灰 / `*` / `—/—` | ✅（二轮测评补上「计数未知」） |
| 投稿四态 | 按钮文案 / 打回原因 / 等收录计数 / 行出现 | ✅ |
| 统计新鲜/过期/失败 | 计数直接显示 / 无提示（=新鲜或过期但可用） / 「统计暂不可用」 | ✅-（过期无可视，低风险） |

## 6. 模糊状态与静默转移

- **静默转移**：库链从「未加入」到「已启用」在卫月仓库重载完成前有窗口期——二轮测评后已改为**加库成功即就地翻新**（`MarkRepoState`），不再静默等待。
- **模糊**：`[已在库]` 不区分「本机已加但没装插件」与「装了插件」——发现页不承担安装状态，保持现状。
