# 插件发现 — 第三轮评审（pass 3，2026-10-06）

触发：用户一次提出 8 条界面收缩（去勾选项、去箭头占位、去元信息、去内部名/标签、♥ 不带数字、库链两按钮、排版）并要求「再过所有 skill」。本报告是全部 11 个 skill 在本轮的口径。

## 本轮改动（用户点名，全部落地）

| # | 用户要求 | 实现 |
|---|---|---|
| 1 | 去掉「顺手加到我的库」 | 投稿区勾选删除；投稿只进云库（本机加库走行内按钮） |
| 2 | 详情不显示「一行简介」「详情」灰字 | 展开区只留描述正文（无标签） |
| 3 | 去掉内部名 | 展开区不再显示 |
| 4 | 点赞只显示总数、不写「总共」 | 展开区 `点赞 12`（数字前无「本周/总共」字样） |
| 5 | 库链两个按钮 = 加入自己的库 + 复制 | 「在浏览器打开」删除；按钮文案统一 |
| 6 | 右栏 ♥ 不显示数字 | 只画 ♥（未同步时 `♥ *`），计数在 tooltip |
| 7 | 去掉最左边像「=」的分格 | 移除 ▸/▾ 箭头字符（展开态改靠 Selectable 选中底色） |
| 8 | 去掉未点开前的元信息行（作者·库链·日期 等） | 折叠行只剩 图标 + 名称 + 一行简介；元信息全部移入展开区 |

## 本轮评审新修（skill 视角挖出来的）

| ID | 级别 | 问题 | 处置 |
|---|---|---|---|
| P3-1 | 1（无障碍） | ♥ 去掉数字后按钮只有字符宽（命中区过小） | 给最小宽度 `max(40, 字号×2.6)` |
| P3-2 | 1（审美/对齐） | 展开区缩进 25px，和图标右侧文字列不对齐 | 缩进改为 40px 图标列宽 + 间距，与名称同一条视线 |

## 11 个 skill 逐项结论

| Skill | 本轮结论 |
|---|---|
| **design-sense** | 折叠行从三行降到两行、元信息清空后视觉噪音大幅下降；层级回到「名称 > 简介 > 操作」。剩余：详情正文没有标题（用户点名去掉），首次看是一段裸文本——接受。 |
| **heuristic-eval** | H1 状态可见性：♥ 计数只在 tooltip（用户点名），严重度 1，接受；H4 一致性：行内与详情按钮文案已统一为「加入自己的库」；H8 极简：达标；其余 8 条无新问题。 |
| **cognitive-friction-detector** | 摩擦下降：不再需要在行里解析「作者·库链·日期」；新增一处依赖——♥ 的含义靠顶部说明 + tooltip（记忆负担 1）。 |
| **vocabulary-audit** | 术语表更新：`加入自己的库`（UI 统一，弃用「加库」按钮文案）、`复制`、`点赞=总数显示`；删除词条：顺手加到我的库、在浏览器打开、内部名、一行简介/详情标签（仅在展开区不再出现）。 |
| **consistency-audit** | 行/详情/工具条（撤回添加）三处动作语义一致；投稿区去掉本机动作后，「投稿=云库、加入自己的库=本机」的分野更干净。无跨页回归。 |
| **accessibility-precheck** | P3-1 已修（♥ 命中区）；禁用透明度 0.75 保留；行整行可点的大目标保留；对比度不变。 |
| **wireframe-critic** | 行内只有一个主操作（蓝）+ 一个社交动作（♥），权重清晰；详情区改为「正文 → 键值 → 库链」，阅读顺序自然。 |
| **failure-path-audit** | 投稿路径变短（不再有「顺手加到本机」失败点）；「已在云库里」的提示不再带加库动作——文案保留，用户可回列表用行内按钮（在报告 §遗留注明）。 |
| **state-model** | 本机加库的入口只剩行内/详情按钮；状态表其余不变（投稿四态、点赞三态、库链四态）。 |
| **cognitive-walkthrough** | J1：行更好扫；J2：加入自己的库 → 立即 `[已在库]`；J4：投稿只回云端结果，输入保留；三问通过。 |
| **information-architecture** | 不变（扁平单页）；投稿与实践分层更清楚。 |

## 遗留观察（不阻塞）

1. ♥ 不显示数字后，新用户要理解排行榜依据只能看 tooltip（用户点名，保留）。
2. 投稿「已在云库里」不再提供一键加库，需回到列表用行内按钮（两步）。
3. 详情正文无标题（用户点名去「详情」灰字），长描述靠语境理解。
4. 图标策略、键盘 tooltip 可达性同 pass2 遗留。
