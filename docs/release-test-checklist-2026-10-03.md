## 2. 插件汉化 · 行内按钮（互斥与对齐）

- [ ] 未加载的插件：第二槽是**绿色「启用插件」**（点了会加载，之后变「打开/设置」）
- [ ] 已加载的插件：第二槽是**「打开」或「设置」**，同一槽位、宽度与「启用插件」一致
- [ ] 「打开」有主界面开主界面；只有设置开设置；都没有则置灰（悬停有说明）
- [ ] 行内按钮**最多四个**且与其它行对齐（主按钮 / 打开或启用 / 还原原文 / 一键上传）
- [ ] 悬停提示文案正确（打开主界面。/ 打开设置页面。/ 插件当前没有加载，先启用它。等）
- [ ] 点整行任意处展开/收起详情（行内没有「详情」按钮）
- [ ] 行首有 **▸/▾** 展开指示；悬停提示「点这一行展开：重新抽取 / 编辑校对 / 云端译文」

## 3. 一键汉化全流程

- [ ] 未汉化插件点「一键汉化」：首次弹「选择翻译方式」（或用已配置的通道）
- [ ] 翻译进行中：行上进度条 + 工具条显示「正在汉化 X：…」+ 可取消；取消后已翻条目保留
- [ ] 完成后：自动写入 DLL 并重载，行变「已汉化 N 条」，游戏里插件界面变中文
- [ ] 同一个插件再点一次：只补新增文本，不重复翻（速度明显更快）
- [ ] 失败场景（可断网或临时改错 API key）：行显示「失败」+ 原因 + 主按钮变「重试」；重试能接着翻
- [ ] 翻译完成后翻译设置入口可用（行内 note 或工具条「翻译设置…」）

## 4. 写入、还原与备份

- [ ] 「有改动待写入」状态：主按钮变「写入并重载」，点了只写不重翻
- [ ] 「还原原文」：确认框默认焦点在「取消」；确认后还原 + 自动重载，界面回英文
- [ ] **已加载插件**也能还原（不报红、不冲突）
- [ ] 还原后备份仍在（行上仍可再「一键汉化」）
- [ ] 还原后原文件哈希与备份记录一致（可选：对照 `FireGazeData\uit-originals\<插件>\*.orig`）
- [ ] 插件更新后（版本变了）：行显示「需要重打」，一键汉化会按新版本重打

## 5. 快捷键/边角（列表）

- [ ] 「中文插件」行：没有「一键汉化」「一键上传」，只有启用/还原（视状态）；悬停提示为「中文插件：本身就是中文界面，FireGaze 不抽取 / 不翻译 / 不打包 / 不上传。」
- [ ] 点「中文插件」行的「一键汉化」类入口不存在；若旧补丁在，可「还原原文」
- [ ] 「不翻」标记的条目不会被写入补丁
- [ ] 3000+ 条的大插件（如 BossModReborn / AutoHook）抽取+翻译不卡界面

## 6. 编辑器（编辑校对）

- [ ] 行展开 → 「编辑校对…」打开编辑器
- [ ] 搜索、逐条编辑、保存（Ctrl+S 或按钮）
- [ ] 「不翻」勾选：该条不再进补丁；取消勾选可恢复
- [ ] 灰名单勾选框（「连灰名单一起翻译」）默认跟随全局设置，仅本次编辑生效
- [ ] 「重新抽取」更新候选（含 TranslationTable 修订，不会拿旧词表报缺译）
- [ ] 「更多 → 提交人工译文到公共库…」：只提交人工译；**体检不过的条目被列出来且不提交**

## 7. 一键上传（本轮新增：本地体检）

- [ ] 有译文的行点「一键上传」：弹出确认框，写清「发什么 / 去哪 / 公开性」，默认焦点在「取消」
- [ ] 弹窗里有「会变成一个公开的 GitHub issue（所有人都能看到）」与「中继不可用时需要你在网页按 Submit」两句说明
- [ ] 全部健康时：显示「本地检测：译文全部通过。」，按钮为「上传 N 条」
- [ ] 人为制造问题条目（编辑器里把某条译文改成与原文相同、或删掉 `{0}`）：上传弹窗出现「本地检测：M 条没过，不会上传——」+ 清单（原文 + 原因）；按钮仍可上传健康条目
- [ ] 全部有问题时：按钮只有「关闭」，不会上传；行上有「本地检测：M 条都有问题，没有上传」提示
- [ ] 日志出现 `[上传检测]` 记录（有不健康条目时）
- [ ] 上传成功：行上提示成功，浏览器/issue 链接正确（relay 可用时）或回退到 GitHub 提交页
- [ ] 上传失败：提示可复制内容，不谎报成功
- [ ] 在编辑器里给某条译文勾上「不翻」后，再「一键上传」：这条不再出现在上传清单里（资源 / 属性同理）
