# FireGaze 静态分析审计（2026-10-02）

工业式审计的落地记录：**基线 → 分类 → 真问题修复 → 风险评估（豁免要写理由）→ 测试有效性验证**。
本文件是「全开分析器」那次审计的档案；日常构建**故意不开** `AnalysisMode=All`（理由见「处置」）。

## 一、范围与方法

- **工具**：.NET 内置 Roslyn 分析器（`AnalysisMode=All`、`AnalysisLevel=latest`）+ NuGet 依赖漏洞扫描。
- **范围**：`src/FireGaze` 全部（约 3 万行）。
- **复现命令**：

  ```bash
  dotnet build src/FireGaze/FireGaze.csproj -c Release -t:Rebuild -p:AnalysisMode=All -p:AnalysisLevel=latest
  dotnet list src/FireGaze/FireGaze.csproj package --vulnerable --include-transitive
  ```

- **交付前例检**：`-t:Rebuild`（0 警告）+ fgtest + 依赖漏洞扫描。（增量构建会跳过未变更文件、可能掩盖警告——用 `Rebuild`。）

## 三、处置

### 已修复（1.2.0.98）

| 规则 | 位置 | 处置 |
|---|---|---|
| CA5392 | `UIText/DPAPI.cs` 三个 P/Invoke | 加 `[DefaultDllImportSearchPaths(DllImportSearchPath.System32)]`（明确系统 DLL 搜索路径） |
| CA2000 | `RepoAudit/RepoScanner.cs` 的 `SemaphoreSlim` | 改 `using var`（`Task.WhenAll` 之后才出作用域，闸门全程有效） |
| CA1508 | `UIText/FFXIVGlossary.cs` 双检锁 | 字段加 `volatile`（发布可见性）。分析器报「恒 false」是**不理解多线程双检锁的误报**，代码保留 |

### 已评估、不修（风险评估记录）

| 规则 | 位置 | 理由 |
|---|---|---|
| CA5350 | `RepoAudit/IconCache.cs` 用 SHA1 | **非安全用途**（URL → 缓存文件名，截断 64 bit）。换 SHA256 会让全部图标缓存失效重下：收益为零、副作用真实。接受。 |
| CA5399 | `UIText/TranslationChannels.cs` 未开证书吊销检查 | .NET 默认；吊销检查依赖在线 CRL/OCSP，在部分网络下会让翻译整体不可用——可用性优先。接受。 |
| CA2000 | `TranslationChannels.CreateClient` 的 handler | 误报：handler 与 client 同寿命，client 是 `static readonly` 长期复用（.NET 推荐形态）。 |
| CA1001 | `UITextEditorWindow.translateCancel`、`UITextTab.Run.Cancel` | CTS 生命周期与持有者一致，未访问 WaitHandle 时无内核资源；对象回收即释放。低风险，接受。 |
| CA1031（344 条） | 各处的 `catch (Exception)` | **设计策略**：插件边界必须防御性捕获（崩游戏 vs. 降级+日志）。抽查确认全部有日志或错误返回，**无静默吞噬**（空 catch 扫描 = 0）。接受。 |
| CA1507 / CA1305 / CA1307 / CA1308 / CA1822 / CA1054 / CA1056 / CA1002 / CA2234 / CA1062 / CA1869 … | 风格 / 性能 / API 形态 | 非缺陷；不逐个改（大量无收益 diff）。下次把分析器等级提进 csproj 时，用豁免基线一次性处理。 |

### 测试有效性验证（变异测试，手工版）

工业做法：**故意破坏实现，验证测试真的会报警**（否则断言是「假绿」）。本次抽两处：

| 变异 | 预期 | 结果 |
|---|---|---|
| `UITextText.LooksLikeSentenceKey` 的短文本分支返回 `true` | fgtest 的负例断言失败 | **抓到**（exit=1，报 `no_matches.title` / `Save` / `1st Person Camera` 等 4 条），且连带触发「工厂 key 不进候选」的键名防护断言 |
| `UITextPackEntry.IsPatchable` 对 Excluded 返回 `true` | 「Excluded 硬拦」断言失败 | **抓到**（exit=1） |

结论：这两块防护的测试是活的；变异已全部还原（`git checkout`）。

## 四、上一轮（2026-10-02，1.2.0.97）的运行时修复

静态分析之外，对「跨线程共享状态」的深审发现并修复：

- `notes` / `enabling` / `uploading` 三个界面容器被**后台任务线程写、界面线程读**（普通 Dictionary/HashSet 属未定义行为）→ `ConcurrentDictionary`。
- `InstalledPluginsIndex` 索引构建**逐条容错**（单插件反射失败不再让整张表「不可用」）；顺带修 `Plugin.Log` 空解引用警告。
