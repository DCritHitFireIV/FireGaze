## 1. 一句话结论

**v5 是一次「把还原图对齐实现」的忠实复刻：v4 已修的 12 类问题在代码里大都找不到残留，但本轮实现改动自己引入了 3 个 P1 级文案/入口问题（展开入口不可见、「详情」遗留指引、上传公开性披露被删回退），另有 1 个 P1 是 v4 修复没做全（「应用云端译文」引导仍写「一键汉化」，实机按钮是「写入并重载」）。此外还原图虽然标称「忠实复刻」，仍有 6 处与实现不符（行序、同时展开两行、简介配色、模态位置、按钮底色、问题清单边框），不能用它当实现规格。建议先修 4 条 P1（全为一行文案/一个指示器级别），其余 P2 批量处理。**

## 9. Synthesis（SKILL.md 强制三节）

3. **「应用云端译文」引导到不存在的按钮名（V4-01，P1）**：v4 的同族修复漏了两处（弹窗 + 完成提示）。

5. **状态/库名多套叫法 + 「待处理」无对应筛选（V1-04/V1-05/V2-01，P2）**：本页唯一兜底信号只能看数字、不能落到行。

**Quickest wins（全是字符串/一行样式）**
- `UITextTab.cs:1806`、`:1298` 去掉「详情」；
- `:1455`、`:1495` 的「一键汉化」→「主按钮（写入并重载）」；
- 恢复一句公开性（V3-01）；
- `:606` 简介改 muted 色（V1-06）；
- `:1030`「本地检测：译文全部通过」改绿（V3-03）；
- 行尾加 ▸/▾（P1-1，10 行）。

**需要重做结构而不是视觉微调的问题**
- **「展开即入口」的可发现性**：不是加个箭头就完事——需要决定「详情/编辑校对/云端译文」是留在展开区（那就要有指示器 + 收起 + 键盘可达），还是给「编辑校对…」一个行内常驻次级入口。建议先定这个，再决定箭头。
- **状态与动作词汇表**：先把「未翻 / 已翻未写入 / 已写入 / 需重打 / 失败」五个状态各定一个唯一词，再让徽标、筛选、计数、详情串、确认框共用（v4 报告已把 N1/N5/N6 归为同一族；本轮 V1-04/V1-07/V2-01 是同族残留）。
- **「待处理」的可操作性**：把计数做成可点筛选（口径 = `NeedsAttention`）——这会把「感觉有 7 个要处理」变成「一眼列出这 7 个」，是本页第一优先级用户（重度玩家、反复扫 194 个插件）价值最高的一次结构改动。
